# subfount

[![fount repo](https://steve02081504.github.io/fount/badges/fount_repo.svg)](https://github.com/steve02081504/fount)

**subfount** — это лёгкий клиент, который подключает ваше устройство к сети [fount](https://github.com/steve02081504/fount).
Он запускает оверлейную инфраструктуру fount (`infra`) на вашей машине и, подключившись к хосту, становится вспомогательным узлом, через который умные агенты хоста могут выполнять код или команды оболочки на вашем устройстве.

## Возможности

- **Участие в infra** — присоединяется к оверлейной сети fount и участвует в пересылке пакетов и почтовых ящиках, поддерживая работоспособность сети.
- **Рабочий узел хоста** — после подключения к хосту становится вспомогательным узлом: хост может отправлять ему запросы `run_code` (выполнить произвольный скрипт) и `shell_exec` (выполнить команды оболочки).
- **Приоритетная поддержка хоста** — получает таблицу репутации от хоста, доверяет его узлам и даёт хосту приоритет в поддержке infra.
- **Автономно или с поддержкой** — без настроенного хоста работает как автономная infra; с хостом одновременно запускает infra и поддерживает хост.
- **Горячая конфигурация** — изменение `data/config.json` во время работы вступает в силу без перезапуска (демон следит за файлом).
- **Панель TUI** — встроенная интерактивная панель конфигурации для изменения параметров подключения, переключения infra и запуска/остановки демона.

## Требования

- [Deno](https://deno.com) (автоматически устанавливается runner'ом при отсутствии)
- Node.js/bun (необязательный запасной вариант)
- PowerShell (Windows) или bash (Linux/macOS) для скриптов runner

## Быстрый старт

Клонируйте или скачайте этот репозиторий и запустите runner в корне репозитория:

```sh
# Linux/macOS
./run.sh

# Windows (PowerShell)
.\run.bat
```

Запуск без аргументов открывает панель конфигурации и запускает демон в фоновом режиме.

## Использование

Основные точки входа — скрипты runner (`run`, `run.bat`, `run.cmd`, `run.sh`) и командный лаунчер в `path/` (`subfount`, `subfount.bat`, `subfount.ps1`, `subfount.mjs`).

### Панель конфигурации

```sh
subfount open        # или: run.sh (без аргументов)
```

Панель позволяет:

- Задать **ID комнаты хоста** и **пароль** (оставьте пустым для режима только infra)
- При необходимости задать **nodeHash** хоста (из API кода подключения)
- Переключать **участие в infra**
- Просматривать статус демона (PID, nodeHash, режим, подключённый хост)
- **Запускать** / **останавливать** демон

### Запуск демона напрямую

```sh
subfount                                    # только infra (из data/config.json)
subfount <host-room-id> <password> [node-hash]
    # infra + рабочий узел хоста / приоритетная поддержка (одноразово, не сохраняется)
```

### Другие команды

| Команда | Описание |
| --- | --- |
| `subfount open` / `subfount panel` | Открыть панель конфигурации |
| `subfount server` | Запустить демон в фоновом режиме на переднем плане |
| `subfount background keepalive` | Запустить демон в фоне с автоматическим перезапуском |
| `subfount keepalive` | Запустить демон с автоматическим перезапуском / переинициализацией |
| `subfount shutdown` | Корректно остановить демон |
| `subfount reboot` | Перезапустить демон |
| `subfount version` | Показать версию и информацию git |
| `subfount update` | Обновить subfount и Deno |
| `subfount clean` | Очистить кеши Deno |
| `subfount remove` | Удалить subfount |
| `subfount debug` | Запустить с отладочным журналом |

## Конфигурация

Демон читает `data/config.json`. Панель редактирует его за вас, но вы также можете редактировать его вручную, пока демон работает (он применяется при следующей попытке подключения).

```json
{
	"hostRoomId": null,
	"password": null,
	"hostNodeHash": null,
	"infra": true
}
```

## Файлы состояния

- `data/daemon.pid` — PID демона
- `data/status.json` — оперативный статус, записываемый демоном (для режима только чтения панели)
- `data/daemon.log` / `data/daemon.err.log` — журналы вывода демона

## Разработка

```sh
deno task start     # запустить демон
deno task panel     # открыть панель
deno task test      # запустить тесты
deno task lint      # линт
deno task check     # проверка типов
```
